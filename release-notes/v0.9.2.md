## Upgrade

Run the installer again on each machine, and on the machine that runs your
server:

```bash
curl -fsSL https://github.com/l7aromeo/user-memory/releases/latest/download/install.sh | sh
```

On Windows, in PowerShell:

```powershell
irm https://github.com/l7aromeo/user-memory/releases/latest/download/install.ps1 | iex
```

- The store keeps its format (schema version 6), so nothing is migrated,
  and 0.9.1 can still open it.
- **Setup now rewrites the store once it has backed it up.** It does this
  each time it runs on a store with memories. The installer's Docker server
  gets the same through its upgrade. The first rewrite after upgrading
  removes text forgotten with earlier versions, which stayed in the store
  file's free space, and the file may shrink.
  - On a store of 100,000 memories the rewrite takes about a third of a
    second.
  - If another program holds the store for more than 30 seconds, setup
    skips the rewrite with a note, and the next setup tries again.
  - Backups made before the upgrade still hold that text. To remove every
    copy, see
    [forget](https://github.com/l7aromeo/user-memory/blob/main/docs/cli.md#forget).
- A server run from a checkout's `compose.yaml` gets the rewrite with
  `docker compose run --rm memory migrate`.
- Codex's hooks are unchanged, so Codex needs no new approval.

## Fixed

- **Forgotten text no longer stays in the store's files.** This covers a
  forget, a correction, and an import that replaces memories. Each now
  removes the old text from the store file, its log and its search index,
  so a backup made afterwards doesn't hold it. Forget and update take about
  0.1 s longer on a store of 100,000 memories.
- **Automatic backups now copy changes followed by a quiet stretch.** The
  server an agent session runs, and the Docker server, back up changes
  once the store has had no change for an hour, and as they stop. That
  backup replaces the day's backup. A store that hasn't changed since its
  newest backup gets no further copy.
- On Windows, a backup failed when a program was reading the day's backup
  as the server replaced it, such as `user-memory backup list` or a virus
  scanner. The server then skipped its backups for an hour, including the
  one as the session ended. It now waits up to two seconds for the reader.
  After any failed backup, the backup as a session ends still runs.
- On the machine that runs the installer's Docker server,
  `user-memory embedding show` and `user-memory embedding sync` now work
  instead of sending you into the container: `show` prints the setting and
  the container's probe, and `sync` runs in the container. Run inside the
  container, `user-memory embedding set` and `user-memory embedding off`
  fail at once, without probing the endpoint first, and say to run them on
  the container's machine.
- When the embeddings endpoint answers with an error, the error now ends
  with the endpoint's own reason, such as a model it doesn't have, a wrong
  API key or a broken Ollama install. Before, it gave only the HTTP status.
  The reason is cut to 300 characters, and the API key is masked if the
  endpoint repeats it.
- An uninstall that removes the store no longer leaves a `backups` folder
  behind when a backup runs at the same moment.

## Docs

- **What forgetting leaves.** The privacy notes list what still holds a
  forgotten memory: older backups, upgrade and repair backups, exports,
  session files and an embeddings endpoint. The forget docs say how to
  remove every copy.
- **Protecting the store and its copies.** The privacy and backup docs say
  how to protect the store if a disk is lost (full-disk encryption), and
  how to protect exports and backups that leave the machine.
- **What `user_confirmed` proves.** The memory model says what the server
  can and cannot check: it checks that `user_confirmed` is given where it
  is required, not that a person gave it.
- The Docker server docs' note on reaching Ollama from Linux now names
  Docker Engine.
