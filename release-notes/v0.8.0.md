## Upgrade

Run the installer again:

```bash
curl -fsSL https://github.com/l7aromeo/user-memory/releases/latest/download/install.sh | sh
```

On Windows, in PowerShell:

```powershell
irm https://github.com/l7aromeo/user-memory/releases/latest/download/install.ps1 | iex
```

- The store keeps its format, so nothing is migrated and nothing needs your
  input.
- Restart Claude Code and Codex, and start new sessions, so agents load the
  updated tools.
- Codex's hooks are unchanged, so Codex needs no new approval.
- `update` keeps a memory's stated reason through a correction, as it keeps
  the evidence; give `reason` to replace it, or an empty one to clear it.
  Before, a content fix erased it. Anything that relied on a content update
  clearing the reason now passes an empty `reason`.
- Rewording an observation or a pattern (its title, context, reason or
  evidence) keeps its source and status: it no longer becomes something
  you stated. Changing its content, type, category, scope or project, or
  confirming it, still makes it yours.
- Scripts that read the JSON of `read` and `search`: a memory's empty
  fields are now left out. Empty texts (`reason`, `context`, `evidence`,
  `project` of a global memory), empty lists (`origins`, `evidence_ids`)
  and nulls (`last_confirmed_at`, `superseded_by`) no longer appear; a
  missing field is empty. Exports keep every field.
- `search` returns 20 matches a page by default, instead of 100, with
  `next_cursor` for the rest; `page_size` (`--page-size`) asks for up to
  200. `index` and `read` by category keep pages of 100.
- A tool call that fails now reaches the agent's client marked as an
  error (`isError`), with the same text. The CLI's memory commands, run
  against a server, exit with a failing status and the server's reason,
  instead of printing its error JSON and exiting 0.
- A server run from a checkout of the repository with its `compose.yaml`
  (not the installer's server), started before 0.7.0: Compose now warns on
  every `up` that its volume was created for another project. That is
  harmless: the volume keeps its memories and is used as it is.
  [Development](https://github.com/l7aromeo/user-memory/blob/main/docs/dev/development.md#a-server-built-from-the-checkout)
  says how to move such a server to the pinned name.

## New

- **Short ids everywhere.** `update`, `forget` and `record`'s `confirms`,
  `supersedes`, `distinct_from` and `evidence_ids` accept the 8-character
  id the index shows, as `read` does.
- **Forget says what it touched.** `forget` reports `staled` (patterns that
  went stale) and `left_superseded` (memories the forgotten one had
  replaced); `update` brings such a memory back, with your yes
  (`revived`).
- **Review that remembers your choice.** Review lists each member's title,
  and `keep` (CLI `--keep ID`, repeatable) leaves a group you choose as it
  is, so review stops proposing it. Review also takes `--projects` on the
  command line.
- **Quieter prompts across a workspace.** The prompt hook keeps every
  project a session has seen as the agent moves between folders, so
  working across a workspace and its repositories no longer fills each
  prompt with notices. A memory whose project leaves is marked `<` with
  "(project no longer loaded)", not as no longer active.
- **Gentler tool calls.** `search` takes `query` for `topic`, and the tools
  take `limit` for `page_size`. Search results say whether they searched
  by meaning (`semantic`). The CLI takes `--projects` for `--project` on
  `index`, `read` and `search`. `link` without an `origin` says where to
  find it, and `index` says "Memory unavailable" only when the store
  fails.
- **Smaller tool schemas.** Fields only user-memory's own client uses are
  no longer in the tools agents load; they are still accepted.
- **Export or import one checkout's memories by folder.** On the command
  line, `user-memory export` and `import` take `--project .` (or another
  folder) as `read` does, naming that checkout's project.
- **Import says what to do next, when there is something.** After an
  applied import, the summary's `next` suggests review when imported
  memories resemble stored ones, and an optional reindex when memories were
  added; on a client of a server it names where reindex runs. A preview no
  longer has one.
- **A missing export lists the ones there are.** Asked for an export name
  that is not in the exports directory, the import tool lists the newest
  names there, so an agent can ask which one the user means.

## Fixed

- `record`'s refusal of a title that is too long says how many characters
  to remove.
- The session start's hint to link another repository says "unless the
  Projects line already lists it", so agents stop linking projects the
  session already loads.
- `user-memory doctor` run inside the installer's Docker server, as the
  docs say, checks the server's store again, instead of stopping because
  nothing is installed in the container.
- `user-memory doctor` shows each embedding setting on one line, also when
  it came through Docker.
- The third-party notices list the dependencies only the Windows builds
  use. v0.7.0's `THIRD_PARTY_NOTICES.txt` has been replaced with the
  complete one.
- The export tool's description says it takes `read`'s filters, so an agent
  asked for part of the memories does not export them all.
